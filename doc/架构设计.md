## 3. 分层职责

| 层 | 职责 |
|----|------|
| Controller | 参数校验、调用 Service、返回 `success()` / `fail()` |
| Service | 业务编排、事务、状态机、调用 ChainAdapter |
| Model | Eloquent + `tableSchema()`，无复杂业务 |
| ChainAdapter | 查块、查 tx、估 fee、广播（广播可走 Signer） |
| Queue Consumer | 异步出金、回调重试、归集 |
| Process/Timer | 周期性扫描链、过期订单 |

## 4. 链上适配层

### 4.1 接口约定

```php
interface ChainAdapterInterface
{
    /** @return 'TRC20'|'BEP20'|'ERC20' */
    public function chain(): string;

    public function validateAddress(string $address): bool;

    /** 查询地址 USDT 余额（最小单位或 decimal 字符串） */
    public function getUsdtBalance(string $address): string;

    /**
     * 扫描区块/地址入账（由 Scanner 调用）
     * @return list<array{tx_hash:string, from:string, to:string, amount:string, block_number:int, confirmations:int}>
     */
    public function fetchIncomingTransfers(string $address, ?int $fromBlock = null): array;

    /** 广播已签名 raw tx，返回 tx_hash */
    public function broadcastSignedTx(string $signedHex): string;

    public function getConfirmations(string $txHash): int;

    public function estimateTransferFee(string $from, string $to, string amount): string;
}
```

### 4.2 TRON（TRC20）要点

- 节点：TronGrid / 自建 FullNode（配置 `TRON_API_URL`、`TRON_API_KEY`）  
- USDT 合约：`TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t`（主网）  
- 确认数：建议 **19**（可配置）  
- 能量/带宽：出金前检查热钱包资源，不足时触发能量租赁或 TRX 补充告警  

### 4.3 扩展 BEP20 / ERC20

通过 `ChainFactory::make('TRC20')` 获取适配器；新增链仅实现 Adapter + 平台配置，不改订单主流程。

## 5. 地址与密钥

### 5.1 地址模型

| 类型 | 用途 | 存储 |
|------|------|------|
| `deposit` | 入金派生地址 | `pa_wallet_addresses`，仅存 address + derivation_index |
| `hot` | 出金广播 | 配置表或环境变量，私钥加密 blob |
| `cold` | 冷存储 | 仅监控余额，不参与自动出金 |

**HD 派生**（推荐）：

- 助记词/ xprv 仅存于部署密钥（`.env` 或 KMS）  
- 派生路径示例：`m/44'/195'/0'/0/{index}`（TRON）  
- 每入金单分配递增值 `derivation_index`，地址与 `order_id` 绑定  

### 5.2 签名策略

| 方案 | 适用 |
|------|------|
| A. 进程内签名 | 开发/低量级；`TronAdapter` 直接读加密私钥 |
| B. 独立 Signer HTTP | 生产推荐；Webman 提交 unsigned tx，Signer 返回 signed |
| C. 硬件/KMS | 大额生产 |

V1 文档按 **方案 A** 实现，架构预留 **方案 B** 接口。

## 6. 商户账务（账本）

采用 **商户虚拟账户 + 流水**，不直接改余额字段：

```
pa_merchant_accounts     available, frozen（冗余快照，事务内更新）
pa_merchant_ledger       每笔变动：deposit / withdraw_freeze / withdraw_success / fee ...
```

**入金 success**：`available += net_amount`  
**出金创建**：`available -= amount`, `frozen += amount`  
**出金 success**：`frozen -= amount`, 记 fee  
**出金失败/驳回**：`frozen -= amount`, `available += amount`

所有变动在 **同一 DB 事务** 内完成，流水表 `balance_after` 便于对账。

## 7. 异步与定时

### 7.1 Redis 队列

| 队列名 | Consumer | 说明 |
|--------|----------|------|
| `pay_withdraw_broadcast` | WithdrawBroadcastConsumer | 审核通过后广播 |
| `pay_webhook` | WebhookRetryConsumer | 回调商户，失败重试 |
| `pay_collection` | CollectionConsumer | 归集（V1.1） |

配置参考现有 `config/plugin/webman/redis-queue/process.php` 中 `export` 队列写法。

### 7.2 定时任务

| 任务 | 周期 | 说明 |
|------|------|------|
| ChainScanner | 3–10s / 新区块 | 拉取 pending 地址入账 |
| ConfirmChecker | 30s | 更新 confirming 订单确认数 |
| OrderExpire | 1min | pending 入金单过期 |
| HotWalletMonitor | 5min | 余额/能量告警 |
| WebhookCompensate | 5min | 扫描 failed 回调补偿 |

使用 Webman `process` + `Workerman\Timer` 或 crontab 调用 `php webman pay:scan` 等 Command。

## 8. Webhook 设计

**触发时机**：订单进入终态或关键态（如 `reviewing` 可选）。

**请求**：

```
POST {merchant.notify_url}
Content-Type: application/json
X-Pay-Timestamp: 1692000000
X-Pay-Signature: HMAC-SHA256(body, merchant_secret)
```

**Body 示例**：

```json
{
  "event": "deposit.success",
  "order_no": "D202608191200001",
  "out_trade_no": "M-10086",
  "chain": "TRC20",
  "amount": "100.000000",
  "tx_hash": "abc...",
  "status": "success",
  "paid_at": "2026-08-19 12:05:00"
}
```

**重试**：1m, 5m, 15m, 1h, 6h（最多 5 次），全部失败标记 `webhook_status=failed`，运营可手动重发。

## 12. 关键设计决策（ADR）

| ID | 决策 | 理由 |
|----|------|------|
| ADR-P01 | 表前缀 `pa_*` | 与历史 payment 域一致，和 `sy_*` 系统表分离 |
| ADR-P02 | 一单一址 HD 派生 | 降低串单与对账难度 |
| ADR-P03 | 账本流水 + 冗余余额 | 审计友好，并发用行锁更新 account |
| ADR-P04 | 出金异步广播 | 避免 HTTP 超时，支持重试 |
| ADR-P05 | 恢复 `/api/pay/*` | 充付系统必须对商户暴露 API |
| ADR-P06 | 首期仅 TRC20 | 缩短交付；Adapter 抽象支持扩展 |
